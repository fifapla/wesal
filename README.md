# وصال – نسخة محلية (Node + PostgreSQL)

## التشغيل على جهازك
> ملحوظة: تم تحديث السن إلى قائمة منسدلة 18–80 حسب ملف DB الجديد (نوع العمود INTEGER كما هو، لا حاجة لتعديل الجداول).

1. ثبّت Node 18+ و PostgreSQL.
2. أنشئ قاعدة البيانات:  `createdb -U postgres wesal`   (أو من pgAdmin)
3. انسخ `.env.example` إلى `.env` وعدّل كلمة سر postgres و`WA_NUMBER` و`ADMIN_KEY` و`JWT_SECRET`.
4. `npm install`
5. `npm run db:init`   ← ينشئ الجداول من ملف `spec.js` (يمكنك رؤية الـ SQL بـ `node db/init.js --print`)
6. `npm start` ثم افتح http://localhost:3000  (ومن الموبايل على نفس الشبكة: http://IP-جهازك:3000)
7. أنشئ حساب الأدمن (مرة واحدة): `npm run admin:create` ثم ادخل http://localhost:3000/admin.html بنفس البيانات.

## تحديث مهم عند الترقية من نسخة سابقة
شغّل `npm install` (مكتبة nodemailer الجديدة) ثم `npm run db:init` مرة تانية: بيضيف الجداول الجديدة (favorites, intro_requests) وعمود claimed_at من غير ما يمسح بياناتك. وأعد تشغيل السيرفر بعد أي تعديل في `.env`. ثم `npm run admin:create` لإنشاء حساب الأدمن (مفتاح ADMIN_KEY القديم لم يعد مستخدماً).

## الفلو
تسجيل ← استمارة 4 شاشات ← رقم + كلمة سر + القسم ← شاشة التحقق (كود WSL-xxxx + زرار واتساب)
← المستخدم يبعت الرسالة ← الأدمن يطابق رقم المُرسل مع الرقم المسجل ويضغط "تفعيل" ← الحساب يتفعل تلقائياً عند المستخدم.

## الملفات
- `spec.js` المصدر الوحيد للحقول والشروط (السيرفر والجداول والواجهة كلهم منه).
- `server.js` الـ API، `db/init.js` إنشاء الجداول، `public/` الواجهة (HTML/CSS/JS) والصور الأصلية المستخرجة من Figma.

## الخطوات التالية
- استقبال رسائل الواتساب تلقائياً (WhatsApp Cloud API Webhook) بدل التفعيل اليدوي.
- جوجل بلاي: تغليف نفس الواجهة بـ Capacitor (`npx cap add android`) مع نشر السيرفر على استضافة HTTPS.

## بعد التفعيل (الجديد)
- المستخدم يضغط "تم الإرسال" ← شاشة "استلمنا رسالتك" وتتحدث وحدها كل 5 ثواني، وأول ما الأدمن يفعّل يدخل المستخدم للتطبيق.
- البحث: يشوف الجنس المقابل فقط (والمفعّلين فقط)، مع تصفية بالسن/الإقامة/الحالة الاجتماعية/المؤهل/الصلاة/القرآن/الطول/لون البشرة/الحجاب أو اللحية.
- النجمة ★ تضيف الملف للمفضلة. وفتح الملف يعرض كل البيانات **بدون الاسم الكامل ورقم التليفون**.
- زرار "طلب تعارف عبر الإدارة" يسجل الطلب ويبعت إشعار للأدمن (تليجرام / بريد / واتساب حسب إعدادات `.env`).
- لوحة الإدارة `/admin.html` (بحساب الأدمن فقط): عرض كل المستخدمين وبياناتهم الكاملة، تفعيل/إيقاف/حذف، وطلبات التعارف. عند وصول مستخدم جديد أو طلب جديد تصدر اللوحة صوتاً وتغيّر عنوان التبويب.
- **رسالة التفعيل بدون API:** عند الضغط على "تفعيل" تفتح محادثة واتساب جاهزة برسالة التأكيد على رقم المستخدم، وتضغط إرسال من واتساب الإدارة (ويب أو تطبيق). لو المتصفح منع النافذة، يظهر زرار "إرسال تأكيد واتساب" بجوار المستخدم. نص الرسالة يتغير من `ACTIVATION_MSG` في `.env`.

## الإشعارات (كلها اختيارية وتعمل مع بعض)
- **تليجرام (الأسهل):** أنشئ بوت من @BotFather وضع التوكن في `TELEGRAM_BOT_TOKEN`، وابعت له رسالة، وافتح `https://api.telegram.org/bot<TOKEN>/getUpdates` وانسخ رقم chat id إلى `TELEGRAM_CHAT_ID`.
- **بريد:** إعدادات SMTP (جيميل: smtp.gmail.com والمنفذ 587 وApp Password) و`ADMIN_EMAIL`.
- **واتساب Cloud API:** `WA_CLOUD_TOKEN` و`WA_CLOUD_PHONE_ID` و`ADMIN_WA`. ملاحظة: الرسائل للمستخدم خارج نافذة 24 ساعة تحتاج قالب (Template) معتمد من ميتا، ضع اسمه في `WA_TEMPLATE_ACTIVATED`.
- لو مفيش أي إعداد، بيتكتب الإشعار في الـ console فقط، ولوحة الإدارة فيها أزرار واتساب جاهزة للتواصل اليدوي.

## إنتاج APK / AAB لجوجل بلاي (Capacitor – وليس Flutter)
المشروع ويب (Node + HTML/JS) فلا يُبنى بأمر `flutter`. نغلّف نفس الواجهة بـ Capacitor:
1. ثبّت Android Studio (يأتي معه Android SDK وJDK).
2. من مجلد المشروع:  `npm i @capacitor/core @capacitor/android` ثم `npm i -D @capacitor/cli`
3. عدّل `public/config.js` ليشير لعنوان السيرفر (للاختبار: `http://IP-جهازك:3000`، وللنشر: عنوان HTTPS).
4. `npx cap add android` (مرة واحدة) ثم `npx cap sync android` بعد أي تعديل في `public/`.
5. `npx cap open android` ثم من Android Studio: Build ← Build APK(s) للتجربة، أو Build ← Generate Signed Bundle (AAB) لجوجل بلاي.

> ملحوظة Android: للتجربة على سيرفر HTTP محلي يجب أن يكون `androidScheme` في `capacitor.config.json` هو `http` (وإلا يمنع الـ WebView الاتصال المختلط). عند النشر بسيرفر HTTPS غيّره إلى `https`.

### أوامر Android المختصرة (شغّلها من جذر المشروع، وليس من مجلد public)
`npm run android:add` (مرة واحدة) ← `npm run android:sync` (بعد أي تعديل) ← `npm run android:open`

## نشر مجاني للتجربة من أي مكان (Neon + Render)
قاعدة البيانات على **Neon** (Postgres مجاني دائم، 0.5GB)، والسيرفر على **Render** (مجاني، ينام بعد 15 دقيقة خمول ويستيقظ في نحو دقيقة).
1. **Neon:** أنشئ حساباً على neon.com ← New Project ← انسخ **Connection string** (الذي يبدأ بـ postgresql://).
2. **أنشئ الجداول والأدمن على القاعدة السحابية من جهازك:** ضع الرابط في `.env` كـ `DATABASE_URL` ثم `npm run db:init` ثم `npm run admin:create`.
3. **GitHub:** أنشئ مستودعاً خاصاً (Private) وارفع المشروع (ملف `.env` لا يُرفع، مستثنى في `.gitignore`).
4. **Render:** New ← Web Service ← اربط المستودع. Build: `npm install --omit=dev`، Start: `node server.js`، Plan: Free. المتغيرات: `DATABASE_URL` و`JWT_SECRET` (نص عشوائي طويل) و`WA_NUMBER`. (أو New ← Blueprint ليقرأ `render.yaml`.)
5. افتح الرابط `https://اسم-الخدمة.onrender.com` للتجربة، والإدارة على `/admin.html`.
6. **التطبيق:** ضع الرابط في `public/config.js` (`window.WESAL_API='https://...onrender.com'`) ثم `npx cap sync android` وابنِ الـ APK. أي شخص يثبّته يدخل على نفس قاعدة البيانات. ويمكن أيضاً فتح الرابط مباشرة من متصفح الموبايل وتثبيته كتطبيق.
7. لإبقاء السيرفر مستيقظاً: خدمة UptimeRobot المجانية تزور `/healthz` كل 5 دقائق.

## أيقونة وشاشة بدء التطبيق (Android)
`npm run android:assets` يولّد أيقونات التشغيل وشاشة البدء من مجلد `assets/` (مبني على شعار وصال)، ثم `npx cap sync android` وابنِ من جديد.
